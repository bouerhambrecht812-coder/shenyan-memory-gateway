# 沈砚记忆网关 · Shenyan Memory Gateway

给 AI 角色、虚拟人和数字员工加一层**记得住、查得到、改得动**的长期记忆。

记忆存在自己的库里，写不写进正史由人点头，换一个 Base URL 就能接进现有对话产品。

---

## 这一页是什么

一份产品案例，不是源码仓库。

- **`index.html`** — 完整案例页，图片已内联，双击就能看，无需联网
- **`shenyan-memory-gateway.pdf`** — 同一份内容的 A4 版，9 页，适合打印或当附件

用浏览器打开 `index.html` 即可。这个仓库建成 GitHub Pages 后，根地址就是这个页面。

## 里面讲了什么

| 章节 | 内容 |
|---|---|
| 01 问题 | 角色类产品为什么记不住人，三条断点 |
| 02 产品 | 四项能力、接入方式（三个字段） |
| 03 架构 | 渠道与模型两端解耦，部署脚本怎么落地 |
| 04 记忆模型 | 四步审核回路、三道闸门、为什么不用向量库 |
| 05 证据 | 离线测试、运行日志、端口快照、四张实机截图 |
| 06 商业化 | 三种交付形态、和现成方案的位置关系、路线图 |
| 07 边界 | 合规、平台风险、八条没做好的地方 |

## 技术栈

FastAPI · SQLite · DeepSeek API（OpenAI 兼容协议）· Docker Compose · AstrBot

单实例跑在 2 GB 的云主机上，网关常驻 69.3 MiB，数据一共 212 KB。

## 数据与隐私

- 页面里所有对话都是**合成示例**，不是真实聊天记录
- 不含密钥、服务器 IP、账号 ID
- 截图里的账号信息已打码
- 案例中的角色是虚构人物，由作者与 AI 共同构建

页面源文件不在这个仓库。改完重新生成单文件版后，替换本目录的 `index.html` 和 PDF 即可。
